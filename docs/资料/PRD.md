# 「言权」产品需求文档（PRD）

版本：v1.0 · 2026-08 · 状态：MVP 已交付，待上线

## 1. 产品概述

### 1.1 一句话定位

**用户口述维权经历，AI 自动生成专业投诉信 + 法律依据 + 行动路径 + 沟通话术，全流程一站式解决。**

### 1.2 产品形态

| 阶段 | 形态 | 技术 | 状态 |
|------|------|------|------|
| Phase 1 | 微信小程序 | Taro 4 + React + FastAPI | ✅ 可交付 |
| Phase 2 | iOS / Android App | SwiftUI（已有工程）/ Taro RN | 后续迭代 |

### 1.3 品牌

- 产品名：**言权**（寓意"言语即权利"）
- Slogan：**口述即出信，维权有依据**
- 视觉：深海蓝 + 鎏金，专业法律质感

## 2. 市场背景与痛点

### 2.1 市场数据

- 2025 年全国投诉总量 **2036.6 万件**，首次突破 2000 万，同比 +9.3%（国家市场监管总局）
- 网购投诉占比 **56.9%**（1506.7 万件）
- 全年挽回经济损失 **43.5 亿元**
- **约 50% 的消费者遇到问题后放弃维权**

### 2.2 放弃维权的原因

| 原因 | 占比 |
|------|:--:|
| 不会写投诉信、不知道怎么写 | ~60% |
| 不知道找谁投诉 | ~50% |
| 怕麻烦、金额小不值得 | ~40% |
| 投诉信被驳回、不知道原因 | ~30% |

**核心洞察**：12315 的"投诉"与"举报"是两条通道，90% 的人选错；投诉信写不好，处理慢、易驳回。普通人缺的不是法律知识，而是一个把"口语化遭遇"变成"专业法律文书"的工具。

## 5. 核心功能需求

### 5.1 输入层（P0）

1. **语音输入**：按住录音 → ASR 转文字 → 可编辑
2. **文字输入**：多行文本，2000 字上限，输入引导（时间/平台/商品/金额/诉求）
3. **订单截图 OCR**：上传截图 → 提取平台、订单号、商品、金额、商家

### 5.2 生成层（P0）

6 步 AI 管线：

1. 事实提取（结构化：平台/商品/金额/时间/商家/问题/诉求/缺失字段）
2. 法律检索（本地知识库语义匹配 1-3 条 + 预留北大法宝）
3. 投诉信生成（被投诉方 + 事实经过 + 法律依据 + 明确诉求 + 威慑语句）
4. 商家资质建议（7 类资质查验指引）
5. 自我审查（LLM 质检 + 自动修复）
6. 话术模板（商家 → 平台 → 12315 三段式）

### 5.3 展示层（P0）

- 结果页：维权路径时间线、渠道建议（协商/投诉/举报/诉讼）、法律依据、投诉信（可编辑）、话术（可复制）、资质建议、补充建议
- 一键复制投诉信、分享

### 5.3.1 法律溯源（P0）

- 生成结果附带法条全文 + 官方来源链接（国家法律法规数据库 flk.npc.gov.cn）
- 结果页每条法律依据可展开查看原文，一键复制官方检索链接

### 5.3.2 维权证据包（P0）

- 最多 6 张证据截图（订单、聊天记录、物流、支付凭证）批量上传
- 每张图自动 OCR 识别关键信息，随投诉信一起保存
- 详情页展示证据画廊；一键复制「投诉信 + 证据清单 + 提交指引」材料包

### 5.3.3 维权指南（P0）

- 8 大常见纠纷场景（网购假货、食品安全、预付卡跑路等）
- 每个场景含：适用法律、行动步骤、沟通技巧、建议渠道

### 5.3.4 用户反馈（P0）

- 结果页「有帮助 / 需要改进」评价
- 需要改进时支持填写具体问题，反馈数据入库用于迭代

### 5.4 记录层（P0）

- 历史列表（按日期分组、按状态筛选）
- 详情页 + 维权进度追踪（已生成 → 已复制 → 已提交 → 跟进中 → 已解决/已放弃）
- 统计（累计/处理中/覆盖类型）、删除

### 5.5 用户层（P0）

- 微信一键登录（code2session）+ 手机号验证码
- 游客模式可用（数据归属默认用户）

### 5.6 合规层（P0）

- 免责声明（不构成法律意见）
- 用户协议 + 隐私政策页面

## 6. 非功能需求

| 维度 | 要求 |
|------|------|
| 可用性 | 演示模式零配置可运行；接口 90 秒超时 |
| 稳定性 | SQLite WAL、异常统一处理、日志 |
| 安全 | token 鉴权、用户数据隔离（归属校验）、上传文件校验 |
| 可测试 | pytest 30 用例覆盖 API/管线/数据库 |
| 可部署 | Dockerfile 一键容器化，10 分钟可上线 |

## 7. 数据模型

### complaints

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| user_id | TEXT | 归属用户 |
| raw_text | TEXT | 用户原始描述 |
| complaint_letter | TEXT | 生成的投诉信 |
| legal_basis | JSON | 法律依据列表 |
| action_path | JSON | 维权路径步骤 |
| category | TEXT | 投诉类别 |
| order_info | JSON | 订单信息（OCR） |
| status | TEXT | 状态机（6 态） |
| created_at | TIMESTAMP | 创建时间 |

### users / legal_knowledge

用户表（phone/openid/token）与法律知识库表（20+ 条文，标签索引）。
