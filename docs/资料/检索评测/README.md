## 这个目录里有什么

| 文件 | 谁写的 | 说明 |
|------|--------|------|
| `法条索引.md` | 脚本生成（`scripts/gen_law_index.py`） | 108 条法条的 ID、标签、内容摘要，写用例时查阅 |

## 责任边界（重要）

按《言权升级方案与 Codex 提示词》§2.3、§4 的约定：

- **query 的措辞**、文件格式、ID 口径、校验脚本 —— 机械工作，Codex 完成
- **`expected_articles`（这条 query 应该命中哪些法条）** —— 判断标准，**必须作者本人填**

原因很直接：面试官会追问「为什么这条应该命中 148 条而不是 55 条」。
标准是 AI 定的，这个问题就答不上来。

## 字段说明

```json
{"query":"外卖里吃到蟑螂，商家只肯退餐费，我要赔偿医药费","expected_articles":["食品安全法-148","消费者权益保护法-55"],"category":"食品安全","source":"真实","type":"口语vs术语","note":"当前漏检148条"}
```

| 字段 | 必填 | 取值 / 说明 |
|------|------|-------------|
| `query` | ✅ | 用户会怎么说（原话或近似原话），不是法条术语 |
| `expected_articles` | ✅ | 预期命中的法条 ID 数组；ID 写在 `法条索引.md` 里，格式 `法律名称-条号数字`。**留空数组 = 还没标注** |
| `category` | ✅ | 纠纷领域：网购 / 食品安全 / 快递物流 / 预付卡 / 服务 / 产品质量 / 教育培训 / 超范围 … |
| `source` | ✅ | `真实`（线上真遇到）/ `改写`（从真实变形）/ `构造`（补覆盖空白） |
| `type` | 建议 | 覆盖类型，五选一：`口语vs术语` / `错别字简称` / `已知缺陷` / `多诉求混杂` / `超范围`。**这一列是 Codex 加的**，用来保证五类覆盖；不想要可以删，校验脚本会改成提醒 |
| `note` | 可选 | 专门记**已知缺陷**（例如「当前漏检 148 条」）——这些是后面写简历的素材 |
| `expect_abstain` | 可选 | `true` 表示这条 query **应当拒答**（超出消费维权范围）。加了它就视为已标注 |

## 怎么用

```bash
# 1) 读索引，确认法条 ID
open "docs/资料/检索评测/法条索引.md"

# 2) 编辑评测集，把 expected_articles 填上
vim "docs/资料/检索评测/eval_set.jsonl"

# 3) 校验（格式 + ID 是否真实存在 + 覆盖率 + 标注进度）
/opt/anaconda3/envs/rag_env/bin/python scripts/validate_eval_set.py

# 4) 重新生成索引（知识库改动后）
/opt/anaconda3/envs/rag_env/bin/python scripts/gen_law_index.py
```

校验脚本会拦住这几类错误：JSON 写坏、字段缺失、query 为空、**法条 ID 不存在于知识库**、
`source` 取值非法、应拒答却填了预期法条、query 重复。它还会提示哪一类覆盖不足 3 条。

## 关于「真实」用例的来源

言权是**已上线的小程序**，真实用户的输入就是最好的 `真实` 用例来源：
后端 `complaints` 表的 `raw_text` 字段存的就是用户原话。

如果云托管的数据库挂了持久化磁盘，就能直接从库里导出几十条真实 query（脱敏后使用），
比任何构造的用例都有说服力。这件事值得在 P0 之前确认一次。
