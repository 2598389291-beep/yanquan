# 言权 · 消费者权益维权文书助手

> 口述即出信，维权有依据。
>
> 让维权，不再是普通人不敢做的事——用户只需说出/写下维权经历，即可拿到一份规范、可提交的投诉文书，配套证据清单、路径推荐与操作指引。

相关仓库：[法条检索评测中台](https://github.com/2598389291-beep/yanquan-retrieval) · [cn-law-mcp](https://github.com/2598389291-beep/cn-law-mcp)

言权是一款 **AI 消费者维权小程序**：面向 12315、黑猫投诉等平台的「上游文书生产工具」。它不代替平台处理投诉，而是帮普通人把"不知道怎么维权"变成"照着做就行"。

- 产品形态：微信小程序（Taro 4 + React + TypeScript），后端 FastAPI（Python 3.11）
- 开箱即用：**未配置任何 API Key 也可全流程运行**（自动进入规则演示模式）
- 上线能力：配置大模型 / 语音识别 Key 后，生成质量与能力进一步增强
- 已上线微信小程序（个人主体），2026 微信小程序开发者计划参赛作品

## 核心功能

| 模块 | 说明 |
|------|------|
| 多模态输入 | 语音（按住说话 → 转写后确认）、文字、订单/聊天截图（OCR 提取关键信息） |
| 投诉文书起草 | 结构化整理成规范投诉文书：事实、法律依据、诉求完整清晰 |
| 法律知识库 | 108 条高频条文 / 20 部法律法规，RAG 检索 + 白名单校验 + 官方溯源链接 |
| 证据清单 | 按纠纷场景（网购/食品/快递/预付卡等）自动列出"该留哪些证据、怎么留" |
| 路径推荐 | 按纠纷类型自动推荐最合适的投诉路径并说明理由 |
| B 计划 | 商家不回应时的升级路线：12315 行政投诉 / 小额诉讼 / 公开曝光 |
| 行动向导 | 5 步可勾选行动清单（留证→协商→12315→跟进→诉讼兜底） |
| 动态渠道 | 快递→邮政申诉、运营商→工信申诉等对口渠道 + 官方热线一键拨打 |
| 官方入口 | 12315 / 黑猫 / 邮政 / 工信等渠道入口一键复制、热线拨打 |
| 模板与案例 | 10 个高频纠纷即用模板、8 个脱敏维权案例 |
| 轻回访 | 一次性询问处理结果，积累真实解决数据（可忽略） |
| 用户系统 | 邮箱登录（自动注册）+ 微信登录，隐私协议可勾选同意 |
| 运营协同 | 消费 / 客服 / 管理员三类角色，案件认领、管理员分派、状态流转、操作日志与用户进度查询 |

## 技术架构

```
微信小程序（Taro 4 + React + TypeScript）
   │  wx.cloud.callContainer（云调用，内网链路，免域名备案）
   ▼
后端服务（Python FastAPI · Docker · 微信云托管）
   ├── 路由层：complaint / evidence / guide / laws / auth / feedback
   ├── 运营层：RBAC · 案件队列 · 认领/分派 · 状态机 · 操作日志
   ├── 服务层：任务式生成管线 · RAG 检索 · ASR 转写 · OCR · 行动指南
   └── 数据层：SQLite（users / complaints / case_events / legal_knowledge / feedback / usage）
   │
   ├── 阿里云百炼（通义千问：文书起草/质检，可选增强）
   ├── DashScope（语音识别 paraformer / 图像识别 qwen-vl，可选）
   └── 云存储（语音/证据文件中转，规避云调用 100KB 限制）
```

关键设计：

- **任务式分阶段生成**：先返回文书骨架（7-10 秒），再逐步补全，前端用真实进度驱动进度条；
- **防编造**：缺失信息强制【请补充】占位，代码级净化 + 知识库白名单校验；
- **双模式**：未配置 Key 时纯规则管线可完整演示；配置后 LLM 增强；
- **降级策略**：管线每一步失败均回退规则实现，任何情况都有结果。

## 运营协同能力

当前已完成 P0 的后端基础，运营前端仍待开发：

| 能力 | 状态 | 说明 |
|------|------|------|
| RBAC | 已完成 | `consumer / agent / admin` 三类角色；客服接口必须登录 |
| 案件队列 | 已完成 | 按状态、类别、关键词筛选；客服只看待认领和自己名下案件 |
| 认领与分派 | 已完成 | 客服认领、管理员分派；重复操作幂等 |
| 状态流转 | 已完成 | `待认领 → 处理中 → 待用户补充 → 已解决 → 已关闭` 的显式状态机 |
| 操作日志 | 已完成 | 与认领/分派/状态变更在同一事务内写入 `case_events` |
| 用户进度 | 已完成 | 案件归属人可通过登录态查看处理进度，不暴露客服账号 |
| 运营控制台 | 已完成最小闭环 | 浏览器访问 `/ops/`，支持登录、筛选、详情、认领、分派和状态流转 |
| SLA | 待开发 | 不把尚未实现的能力写入简历或对外数字 |

管理员初始化方式：先设置 `ADMIN_USER_ID`，该账号登录后自动获得 `admin` 角色；
管理员再调用 `POST /api/operations/users/{user_id}/role` 将其他账号设为 `agent`。

## 快速开始

```bash
# 1. 后端
cd backend
pip install -r requirements.txt
cp .env.example .env        # 按需填入 Key（不填则进入演示模式）
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --app-dir .

# 2. 小程序前端
cd miniapp
npm install
npm run build:weapp         # 产物在 miniapp/dist，用微信开发者工具打开
```

环境变量（全部可选，均可用环境变量覆盖）：

| 变量 | 说明 |
|------|------|
| `DASHSCOPE_API_KEY` | 阿里云百炼 / DashScope Key（不填则规则模式） |
| `WECHAT_APPID` / `WECHAT_SECRET` | 微信登录（小程序后台获取） |
| `ADMIN_USER_ID` | 管理员账号 ID（自动获得 `admin` 角色且不限免费次数） |
| `DATABASE_URL` | SQLite 连接串（默认本地文件） |
